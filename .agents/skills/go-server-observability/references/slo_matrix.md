# مصفوفة أهداف مستوى الخدمة والإنذارات (SLO Matrix & Playbooks)

توفر هذه المصفوفة دليلاً تشغيلياً دقيقاً يحدد أهداف الخدمة (SLOs)، وصيغ الحساب الرياضية، ومستويات الخطورة، وخطوات الاستجابة السريعة عند تجاوز الحدود التشغيلية.

---

## مصفوفة المقاييس والحدود التشغيلية

| المؤشر (SLI) | الهدف (SLO Target) | المعادلة الرياضية | شرط الإنذار (Alert Trigger) | درجة الخطورة |
| :--- | :--- | :--- | :--- | :---: |
| **التوافر (Availability)** | $\ge 99.5\%$ | $\frac{\text{Reqs} - \text{5xx}}{\text{Reqs}} \times 100$ | نسبة `5xx` تتجاوز $0.5\%$ لمدة 5 دقائق متتالية | 🔴 حرج (P1) |
| **زمن الاستجابة (Latency P95)** | $\le 400\text{ms}$ | المئين 95 في النافذة المنزلقة (60s) | استقرار P95 أعلى من $400\text{ms}$ لمدة دقيقتين | 🟠 عالي (P2) |
| **زمن الاستجابة (Latency P99)** | $\le 1000\text{ms}$ | المئين 99 في النافذة المنزلقة (60s) | تجاوز $1000\text{ms}$ في ذروة الزيارات | 🟡 متوسط (P3) |
| **تشبع الـ DB Pool** | $\le 80\%$ | $\frac{\text{ActiveConns}}{\text{MaxConns}} \times 100$ | استهلاك أكثر من $80\%$ من السعة القصوى | 🟠 عالي (P2) |
| **تعطل حجز قاعدة البيانات** | $0$ حجز فارغ | $\text{EmptyAcquireCount}$ | أي زيادة مستمرة في العداد ($\Delta > 0$) | 🔴 حرج (P1) |
| **تسريب الذاكرة (Memory)** | نمو مستقر | $\Delta \text{HeapAlloc} / 10\text{m}$ | نمو الـ Heap بأكثر من $128\text{MB}$ دون عودة | 🟠 عالي (P2) |

## كتيبات الاستجابة التشغيلية (Incident Response Playbooks)

### 1. في حال انطلاق إنذار `High5xxShare`

1. استعلم فوراً عن مصفوفة الأخطاء الأخيرة:

   ```bash
   curl -s http://127.0.0.1:8066/metrics/json | jq '.recent_errors'
   ```

2. طالع ملف سجلات الأخطاء المخصص:

   ```bash
   tail -n 50 logs/error.log
   ```

3. تحقق مما إذا كان الخطأ ناتجاً عن فشل في خدمة خارجية (Third-party API) أو استعلام فاسد في قاعدة البيانات.

### 2. في حال انطلاق إنذار `DBPoolBlocked` أو `DBPoolSaturated`

1. تحقق من عدد الاتصالات النشطة مقابل المتاحة:

   ```bash
   curl -s http://127.0.0.1:8066/metrics/json | jq '.db'
   ```

2. تحقق من الاستعلامات العالقة داخل PostgreSQL:

   ```sql
   SELECT pid, now() - pg_stat_activity.query_start AS duration, query, state 
   FROM pg_stat_activity 
   WHERE state != 'idle' ORDER BY duration DESC;
   ```

3. إذا كانت الاستعلامات طبيعية ولكن الحجم تضاعف، قم برفع `MAX_CONNS` في ملف التكوين وأعد التشغيل الآمن.
