# لوحة مراقبة الطرفية واختبارات التحميل (CLI Monitor & Load Testing)

تتضمن المهارة معايير هندسية صارمة لبناء أدوات المراقبة الفورية للطرفية (Terminal Dashboards) وأدوات اختبار التحميل (Load Testing) لضمان دقة القياس وعدم إرهاق موارد المعالج أثناء المراقبة.

---

## 1. هندسة لوحة التحكم الفورية (`tool/monitor.sh`)

تعتبر لوحة التحكم المعتمدة على الطرفية أسرع وسيلة للمطور ومهندس العمليات لفحص حالة الخادم فورياً أثناء التطوير أو اختبارات الضغط.

### التمريرة الفردية لـ `jq` (Single-Pass Parsing)

- **الخطأ الشائع**: استدعاء أمر `jq` بشكل منفصل لكل حقل (20 إلى 30 استدعاء في الثانية)، مما يستهلك أنوية المعالج في تشغيل عمليات فرعية (Sub-processes).
- **المعيار الهندسي**: استخراج جميع الحقول والمصفوفات في تمريرة واحدة باستخدام `@tsv`:

  ```bash
  read -r rps p50 p95 p99 active_conns max_conns empty_acquires <<< $(
      curl -s http://127.0.0.1:8066/metrics/json | jq -r '
          [
              .traffic.window_rps // 0,
              .traffic.p50_ms // 0,
              .traffic.p95_ms // 0,
              .traffic.p99_ms // 0,
              .db.active_conns // 0,
              .db.max_conns // 0,
              .db.empty_acquire_count // 0
          ] | @tsv
      '
  )
  ```

### استقرار الشاشة بدون وميض (Flicker-Free ANSI Rendering)

- تجنب استخدام أمر `clear` داخل حلقة التحديث؛ لأنه يمسح الشاشة ويعيد رسمها مسبباً وميضاً مزعجاً للعين.
- **الحل المعتمد**:
  1. إعادة المؤشر إلى أعلى اليسار: `printf "\033[H"`
  2. مسح كل سطر حتى نهايته عند الطباعة: `printf "\033[K"`
  مما يضمن ثباتاً مطلقاً للوحة وتحديث الأرقام بانسيابية تامة.

## 2. التحقق من المقاييس أثناء اختبارات التحميل (Load Testing Verification)

عند استخدام أدوات فحص الضغط والتحميل (`tool/loadtest` أو `tool/calibrate_baseline.sh`):

### مبدأ مقارنة الفروقات (Baseline Delta Evaluation)

لا يجوز أبداً تقييم نتائج اختبار التحميل بناءً على العدادات التراكمية الإجمالية للخادم؛ لأنها تحتوي على بيانات سابقة من اختبارات قديمة أو طلبات سابقة.

**الدورة الصحيحة للاختبار**:

1. **أخذ لقطة الخط الأساسي (Capture Baseline)**:
   استعلام `/metrics/json` قبل إطلاق الزيارات، وحفظ:
   - `BaselineRequests`
   - `Baseline5xxErrors`
   - `BaselineWaitCount`
2. **تنفيذ سيناريو الضغط (Execute Load)**:
   إرسال آلاف الطلبات المتزامنة.
3. **حساب الفروقات الصافية للجلسة (Compute Net Deltas)**:
   $$\Delta \text{Requests} = \text{CurrentRequests} - \text{BaselineRequests}$$
   $$\Delta \text{Errors} = \text{CurrentErrors} - \text{BaselineErrors}$$
4. **تقييم أهداف الـ SLO للجلسة**:
   التأكد من أن نسبة الفشل في هذه الجلسة تحديداً تخضع لمعيار الـ $99.5\%$، وأن المئينات المستخرجة من النافذة المنزلقة تمثل ضغط الجلسة بدقة.
