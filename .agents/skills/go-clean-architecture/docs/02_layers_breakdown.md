# تفصيل طبقات المشروع الخمس (Layers Breakdown)

تم تنظيم المشروع داخل دليل `internal/` إلى خمس طبقات متباينة المسؤوليات تضمن الفصل التام بين الاهتمامات:

---

## 1. طبقة النطاق (`internal/domain`)

- **الهدف**: تمثيل الكيانات وقواعد الأعمال المؤسسية (Enterprise Business Rules).
- **المحتويات**:
  - كائنات النطاق (Entities & Value Objects): تراكيب Go بسيطة (Structs).
  - قواعد التحقق وثوابت النطاق (Invariants): دوال تفحص صحة البيانات (مثل أن الرصيد لا يمكن أن يكون سالباً).
  - أخطاء النطاق الصريحة (Domain Sentinel Errors): مثل `ErrInvoiceNotFound` أو `ErrContractExpired`.
- **الممنوعات**:
  - يُمنع تماماً استيراد أي حزم خارجية أو وسوم التنسيق مثل `json:` أو `db:` داخل ملفات النطاق.

---

## 2. طبقة حالات الاستخدام (`internal/usecase`)

- **الهدف**: تنفيذ العمليات وسيناريوهات التطبيق (Application Business Rules).
- **المحتويات**:
  - الـ Interactors: تراكيب تنفذ حالات الاستخدام (مثل `CreatePaymentUseCase`).
  - أوامر الإدخال ومخرجات النتائج (Commands & Queries): تراكيب تمثل المدخلات المنطقية للعملية.
  - تعريف المنافذ (Ports): واجهات Go (Interfaces) تحدد ما تحتاجه حالة الاستخدام من المستودعات الخارجية (Repositories) أو بوابات الدفع دون معرفة كيف تُنفذ.
- **الممنوعات**:
  - يُمنع استيراد حزم الويب مثل `net/http` أو برامج تشغيل SQL مثل `pgx`.

---

## 3. طبقة المحولات (`internal/adapters`)

- **الهدف**: تحويل البيانات بين التنسيق الأنسب لحالات الاستخدام والتنسيق الأنسب للأجهزة الخارجية.
- **الأقسام**:
  - **محولات الإدخال (Driving / Inbound Adapters)**:
    - مسؤولة عن استقبال طلبات HTTP (باستخدام Chi Router مثلاً)، وقراءة مدخلات JSON عبر هياكل DTOs، والتحقق من صحة المدخلات، واستدعاء حالة الاستخدام، وتنسيق الاستجابة المناسبة.
  - **محولات الإخراج (Driven / Outbound Adapters)**:
    - مسؤولة عن تنفيذ واجهات الـ Repositories المحددة في طبقة الـ usecase، وتنفيذ استعلامات SQL، وتحويل صفوف قاعدة البيانات إلى كيانات النطاق (`domain.Entity`).

---

## 4. طبقة البنية التحتية (`internal/infrastructure`)

- **الهدف**: احتواء كافة التفاصيل التقنية الملموسة والبرمجيات الخارجية (Frameworks & Drivers).
- **المحتويات**:
  - إدارة الاتصال بقاعدة البيانات (`pgxpool.Pool`).
  - عميل التخزين المؤقت (Redis Client).
  - بوابات البريد الإلكتروني والرسائل القصيرة والمحاسبة الخارجية (مثل بروتوكول Odoo XML-RPC).

---

## 5. طبقة المنصة والتجميع (`internal/platform`)

- **الهدف**: العمل كـ **جذر التكوين (Composition Root)** للتطبيق.
- **المحتويات**:
  - قراءة الإعدادات البيئية (`config`).
  - تهيئة السجلات (`logger`).
  - حقن التبعيات الصريح (Dependency Injection): إنشاء اتصالات الـ Infrastructure، وتمريرها إلى الـ Adapters، ثم تمرير الـ Adapters إلى الـ Use Cases، وأخيراً ربط الـ Handlers بالموجه (Router).
  - الربط مع دورة حياة الخادم (Server Lifecycle).
