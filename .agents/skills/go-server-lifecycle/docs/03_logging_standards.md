# معايير السجلات المهيكلة (Structured Logging Standards)

السجلات هي "عين" المطور على ما يحدث داخل النظام. تتبنى هذه المهارة معايير `log/slog` الرسمية مع إضافات لتحسين تجربة التطوير والإنتاج.

## نمط السجلات المزدوج (Dual-Mode Logging)

يتم اكتشاف نوع المخرج (Terminal vs File/Pipe) تلقائياً لتوفير أفضل تجربة:

### 1. وضع التطوير (Terminal Mode)
- **التنسيق**: نصي سهل القراءة (Human-readable).
- **الألوان**: استخدام أكواد ANSI ANSI لتلوين مستويات السجل (أخضر للمعلومات، أصفر للتحذيرات، أحمر للأخطاء).
- **الوقت**: تنسيق واضح يشمل التاريخ والوقت مع مؤشر `AM/PM` (مثال: `2025-05-20 10:30:00 AM`).

### 2. وضع الإنتاج (Production Mode)
- **التنسيق**: JSON مهيكل (Structured JSON).
- **الهدف**: سهولة التحليل والفلترة بواسطة أدوات مثل (ELK Stack, Grafana Loki, Datadog).
- **البيانات**: يجب أن تشمل كل رسالة: `level`, `time`, `msg`, `request_id` (إن وجد).

## تقليل الضجيج (Log Suppression)

في الأنظمة عالية الكثافة، تولد طلبات المراقبة (`/metrics`, `/livez`) كميات هائلة من السجلات غير المفيدة.
- **القاعدة**: لا يتم تسجيل الطلبات الناجحة (Status < 400) لنقاط المراقبة.
- **الاستثناء**: يتم تسجيل الأخطاء (Status >= 400) فوراً لضمان اكتشاف المشاكل في نظام المراقبة نفسه.
