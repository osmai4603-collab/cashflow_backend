# صمود الشبكات وقواطع الدوائر (Network Resilience & Circuit Breakers)

عندما تتصل الخدمة بأنظمة خارجية، فإن أي عطل أو بطء في الطرف الآخر قد ينتقل كالعدوى إلى نظامك الداخلي (Cascading Failure). إذا استغرقت كل عملية 30 ثانية لتنتهي بمهلة، فإن جميع اتصالات قاعدة البيانات ومجمعات الخيوط ستستنزف، مما يؤدي لسقوط التطبيق بالكامل.

---

## 1. ضبط مجمعات الاتصال في Go (`http.Transport`)

لا تستخدم أبداً العميل الافتراضي `http.DefaultClient`، بل قم بتهيئة `*http.Transport` مخصص وفق توجيهات Go الرسمية (`go.dev/pkg/net/http/#Transport`):

```go
func NewResilientHTTPClient(timeout time.Duration) *http.Client {
    transport := &http.Transport{
        MaxIdleConns:        100,
        MaxIdleConnsPerHost: 25, // القيمة الافتراضية 2 تسبب استنزاف المقابس ومصافحات TLS مكررة
        IdleConnTimeout:     90 * time.Second,
        TLSHandshakeTimeout: 10 * time.Second,
        ResponseHeaderTimeout: timeout,
        DisableKeepAlives:   false,
    }

    return &http.Client{
        Transport: transport,
        Timeout:   timeout,
    }
}
```

*ملاحظة هامة من توثيق Go*: كائنات `http.Client` و `http.Transport` آمنة للاستخدام المتزامن عبر الـ Goroutines، ويجب إنشاؤها مرة واحدة وإعادة استخدامها بدلاً من إنشائها مع كل طلب.

## 2. قواطع الدوائر (The Circuit Breaker Pattern)

يعمل قاطع الدائرة كوسيط حماية أمامي للخدمة وله ثلاث حالات:

```text
       ┌───────────┐  تجاوز حد الفشل (Failure Threshold)
       │  Closed   ├────────────────────────────────────┐
       │ (طبيعي)   │                                    │
       └─────▲─────┘                                    ▼
             │                                    ┌───────────┐
             │ نجاح طلب التجربة                   │   Open    │
             │                                    │  (مرفوض)  │
       ┌─────┴─────┐                              └─────┬─────┘
       │ Half-Open │                                    │
       │  (تجريبي) ◄────────────────────────────────────┘
       └───────────┘    انقضاء مهلة التبريد (Cooldown Timer)
```

1. **مغلق (Closed)**: الوضع الطبيعي؛ تمر كافة الطلبات إلى المزود الخارجي. إذا تجاوزت الإخفاقات حداً معيناً، ينتقل فوراً إلى حالة "مفتوح".
2. **مفتوح (Open)**: يمنع كافة الطلبات ويرفضها برمجياً فوراً (`ErrCircuitOpen`) دون إرسال أي بايت عبر الشبكة، مما يمنح المزود فرصة للتعافي ويحمي خوادم التطبيق من الاستنزاف.
3. **نصف مفتوح (Half-Open)**: بعد انقضاء فترة تهدئة (Cooldown)، يسمح لعدد محدود من الطلبات التجريبية بالمرور. إذا نجحت، يعود لحالة "مغلق"؛ وإذا فشلت، يعود لحالة "مفتوح".

## 3. التراجع الأسي مع التشتت العشوائي (Exponential Backoff with Full Jitter)

عند حدوث خطأ شبكة مؤقت أو استجابة 503، لا يجب إعادة المحاولة فوراً، بل عبر فترات متباعدة تتضاعف تدريجياً مع إضافة تشتت عشوائي كامل (Full Jitter) لمنع هجوم القطيع العاصف (Thundering Herd):

$$T_{\text{wait}} = \text{random}(0, \; \text{base} \times 2^{\text{attempt}})$$

### قواعد إعادة المحاولة الصارمة
- يُعاد المحاولة **فقط** لعمليات القراءة غير التعديلية (Idempotent Reads)، أو أخطاء الشبكة المؤقتة (HTTP 502, 503, 504).
- **يُحظر تماماً** إعادة المحاولة لأخطاء العميل (HTTP 4xx مثل 400, 401, 403, 422).
- تقتصر محاولات العمليات التعديلية على الحالات التي يتوفر فيها مفتاح عدم التكرار (`Idempotency-Key`).
