# معايير طبقة البنية التحتية والمحولات الثانوية في Go (Go Infrastructure Adapters & Resilience)

تحدد هذه المهارة المعايير الهندسية والإنتاجية الصارمة لتصميم وتنفيذ **طبقة البنية التحتية (`internal/infrastructure`)** في تطبيقات Go وفق المعمارية النظيفة والمعمارية السداسية والمعايير الرسمية لـ Go (`go.dev`).

تركز هذه الطبقة حصرياً على **المحولات الثانوية / الصادرة (Secondary / Driven Outbound Adapters)** التي تربط النظام بالعالم الخارجي ومستودعات التخزين ومزودي الخدمات السحابية. تضمن هذه المهارة عزلاً كاملاً لمكتبات المزودين وبرامج التشغيل عن منطق الأعمال، وحماية الخوادم من انهيارات الشبكة المتتالية (Cascading Failures).

---

## المبادئ الأساسية لطبقة البنية التحتية (Core Principles)

1. **حظر تسريب مكتبات وبرامج تشغيل المزودين (Zero Vendor SDK Leakage)**:
   يُحظر تماماً ظهور أي أنواع أو تراكيب تابعة لمكتبات المزودين الخارجية (مثل برامج تشغيل السحابة، بوابات الدفع، أو عملاء المراسلة) داخل طبقات النطاق (`domain`) أو حالات الاستخدام (`usecase`). تعرّف طبقة النطاق واجهة منفذ نقية (Pure Port Interface)، ويتولى محول البنية التحتية التحويل ثنائي الاتجاه من وإلى كائنات المزود الخارجي.
2. **قاعدة Go الرسمية للواجهات (Accept interfaces, return structs)**:
   تُعرف واجهات المنافذ الصادرة (Ports) في الطبقات المستهلكة (`usecase` / `domain`)، بينما تعيد دوال بناء المحولات في `internal/infrastructure` تراكيب ملموسة (Concrete Structs) تُحقن في جذر التكوين.
3. **نمط سجل المزودين الموحد (Provider Registry Pattern)**:
   عند دعم عدة مزودين خارجيين للوظيفة نفسها (مثل خوادم البريد أو بوابات التخزين أو الدفع)، تُدار المحولات عبر سجل خيوط آمن (`ProviderRegistry`). تطلب حالات الاستخدام المزود المطلوب بواسطة كود تعريفي دون معرفة تفاصيل التطبيق الملموسة.
4. **مهل اتصال صارمة ومقيدة بسياق الطلب (Context-Bounded Timeouts)**:
   لا يُسمح بأي استدعاء شبكي أو استعلام لقاعدة بيانات دون مهلة زمنية قاطعة (`context.WithTimeout`). غياب المهل يؤدي إلى احتجاز خيوط المعالجة ونفاد مجمعات الاتصال عند بطء الخدمة الخارجية.
5. **قواطع الدوائر لإحباط الانهيارات المتتالية (Circuit Breakers)**:
   إذا فشل مزود خارجي بشكل متكرر، يجب أن ينتقل قاطع الدائرة إلى حالة الفتح (`Open State`) ليرفض الطلبات فوراً (Fail-Fast) دون إرسال طلبات شبكية، مما يمنح المزود فرصة للتعافي ويحمي خوادم التطبيق من الاستنزاف.
6. **إعادة المحاولة مع التشتت العشوائي للعمليات الحتمية (Backoff with Full Jitter)**:
   تقتصر إعادة المحاولة على العمليات غير المتغيرة (Idempotent Reads) وأخطاء الشبكة المؤقتة (HTTP 502/503/504). يُحظر تكرار محاولات أخطاء العميل (HTTP 4xx). ويجب تطبيق التشتت العشوائي الكامل لمنع هجمات القطيع العاصف (Thundering Herd).
7. **سلامة العمليات التعديلية المشكوك فيها (In-Doubt Transaction Safety)**:
   إذا انقطعت الشبكة أو انتهت المهلة أثناء استدعاء عملية تعديلية، لا يُفترض فشل العملية ولا يُعاد تنفيذها بشكل أعمى، بل تُصنف فوراً كعملية "قيد التحقق" (Pending Verification) وتُرسل دائماً بترويسة عدم التكرار (`Idempotency-Key`).

## المخطط المعماري لمحولات البنية التحتية

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                      Application Use Cases Layer                        │
│            يستدعي واجهات المنافذ الصادرة (Outbound Ports)               │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                      calls Outbound Port Interface
                      (e.g., EntityRepository, OutboundServicePort)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                    Infrastructure Outbound Adapters                     │
│  ┌───────────────────────────────┐   ┌───────────────────────────────┐  │
│  │   Persistence & Caching       │   │      Provider Registry        │  │
│  │   - PostgresRepositoryAdapter │   │   Thread-Safe Provider Map    │  │
│  │   - RedisCacheAdapter         │   │   "provider_a" ─> AdapterA    │  │
│  │   - S3BlobStorageAdapter      │   │   "provider_b" ─> AdapterB    │  │
│  └───────────────────────────────┘   └───────────────┬───────────────┘  │
│                                                      ▼                  │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │                    Resilience & Isolation Pipeline                │  │
│  │   Context Timeout ──> Circuit Breaker ──> Retry with Jitter       │  │
│  │   ──> Tuned Resilient HTTP Transport (MaxIdleConnsPerHost = 25)   │  │
│  └─────────────────────────────────┬─────────────────────────────────┘  │
│                                    ▼                                    │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │                     Vendor SDK Encapsulation                      │  │
│  │   Converts Domain Request  ──> Vendor Payload                     │  │
│  │   Executes Remote Call     ──> Network / Driver Execution         │  │
│  │   Converts Vendor Response ──> Domain Result                      │  │
│  └─────────────────────────────────┬─────────────────────────────────┘  │
└────────────────────────────────────┼────────────────────────────────────┘
                                     │ Outbound Network / TCP / TLS
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│              Databases, Brokers & Remote Third-Party Services           │
│   PostgreSQL ── Redis ── RabbitMQ / Kafka ── Remote SaaS & APIs         │
└─────────────────────────────────────────────────────────────────────────┘
```

## الممارسات المحظورة (Anti-Patterns)

| الممارسة المحظورة | سبب الفشل في بيئات الإنتاج | البديل المعماري الصحيح |
| :--- | :--- | :--- |
| تمرير كائنات SDK للمزود الخارجي إلى الـ Use Case | ربط منطق الأعمال بمزود معين؛ وتكسر الكود عند تغيير المزود | الالتزام بمنافذ النطاق البحتة وتضمين التحويل داخل المحول |
| استدعاء HTTP خارجي دون مهلة زمنية أو بالعميل العام | يؤدي بطء المزود لتعليق الخادم واستهلاك اتصالات قاعدة البيانات | ضبط مهلة قاطعة عبر `context.WithTimeout` وعميل مخصص |
| استخدام `MaxIdleConnsPerHost = 2` الافتراضي | استنزاف المقابس ومصافحات TLS متكررة تحت الضغط العالي | ضبط `MaxIdleConnsPerHost` إلى 25 أو أكثر في `http.Transport` |
| إعادة المحاولة الأعمى للعمليات التعديلية (`POST`) | تكرار إنشاء الموارد وسحب المدفوعات وازدواجية السجلات | فرض ترويسات `Idempotency-Key` وتصنيف المهلة كـ In-Doubt |
| إهمال ضبط حدود مجمع قاعدة البيانات في `sql.DB` | نفاد اتصالات خادم قاعدة البيانات عند ارتفاع عدد الطلبات | ضبط `SetMaxOpenConns` و `SetMaxIdleConns` و `SetConnMaxLifetime` |
| تجاهل قواطع الدوائر عند توقف الخدمة الخارجية | إغراق الخدمة المنهارة بملايين الطلبات وتجميد خوادم النظام | تفعيل قاطع دوائر يقطع الاتصال مؤقتاً عند تجاوز نسبة الفشل |

## قائمة مراجعة الجودة للبنية التحتية (Infrastructure Checklist)

```text
[ ] جميع برامج التشغيل ومكتبات الطرف الثالث معزولة بالكامل داخل internal/infrastructure
[ ] ينفذ كل محول بنية تحتية واجهة منفذ نقية (Port Interface) معرفة في النطاق
[ ] دوال بناء المحولات تعيد كائنات ملموسة تطبيقاً لقاعدة "Accept interfaces, return structs"
[ ] كل استدعاء شبكي واستعلام قاعدة بيانات محكوم بمهلة زمنية صارمة محددة بالسياق
[ ] مجمعات اتصالات قواعد البيانات مضبوطة الحدود (MaxOpen, MaxIdle, MaxLifetime, MaxIdleTime)
[ ] عملاء HTTP الخارجيون يعتمدون على http.Transport مخصص بمهل اتصال وخمول ملائمة
[ ] قواطع الدوائر مفعلة على الخدمات الخارجية الحرجة مع فترات تهدئة واضحة
[ ] إعادة المحاولة مقيدة بالعمليات الحتمية وأخطاء 5xx الشبكية ومزودة بالتشتت العشوائي الكامل
[ ] العمليات التعديلية تفرض مفاتيح عدم التكرار (Idempotency Keys) لمنع الازدواجية
```
