# استراتيجيات إعادة المحاولة والتراجع الأسي (Exponential Backoff with Jitter)

عندما يتواصل عامل الخلفية مع خدمات شبكية غير مستقرة (مثل خادم بريد خارجي، أو بوابة دفع، أو قاعدة بيانات تحت ضغط مؤقت)، فإن تكرار الطلب فوراً وبمعدل ثابت يزيد الطين بلة ويقود إلى ظاهرة **القطيع الهادر (Thundering Herd)**.

---

## 1. التراجع الأسي (Exponential Backoff)

بدلاً من إعادة المحاولة كل ثانية، تزداد فترة الانتظار بشكل متضاعف مع كل فشل:
$$\text{Interval} = \min(\text{InitialInterval} \times 2^{\text{attempt}}, \text{MaxInterval})$$

---

## 2. أهمية التشويش العشوائي (Jitter)

إذا تعطلت شبكة قاعدة البيانات، وكان هناك 100 خيط معالجة تحاول الاتصال، وبدأت جميعها التراجع الأسي بنفس الصيغة، فإنها جميعاً ستعاود الهجوم في نفس اللحظة بالملي ثانية!

### معادلة الـ Full Jitter الموصى بها

$$\text{SleepDuration} = \text{random}(0, \text{ExponentialInterval})$$
توزيع محاولات العمال عشوائياً يتيح للنظام المتعطل فرصة حقيقية للتعافي التدريجي واستيعاب الطلبات بانسيابية.

---

## 3. احترام سياق الإلغاء أثناء الانتظار

أثناء انتظار فترة الـ Backoff، لا تستخدم `time.Sleep`؛ بل استخدم مؤقتاً يحترم السياق:

```go
timer := time.NewTimer(sleepDuration)
select {
case <-ctx.Done():
    timer.Stop()
    return ctx.Err()
case <-timer.C:
    // المتابعة للمحاولة التالية
}
```
