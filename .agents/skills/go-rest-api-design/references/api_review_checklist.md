# قائمة مراجعة واجهات برمجة التطبيقات (API Review Checklist)

تُستخدم هذه القائمة لمراجعة أي مسار HTTP أو واجهة برمجية جديدة قبل دمجها.

---

## بنود التدقيق

- [ ] هل تعيد كافة الاستجابات الناجحة غلافاً موحداً يحتوي على `"data"` و `"meta"`؟
- [ ] هل تستخدم كافة أخطاء الـ API معيار RFC 7807 (`application/problem+json`)؟
- [ ] هل تحتوي رسائل الخطأ على كود مقروء للآلة (`code`) يسهل ربطه بالواجهات الأمامية؟
- [ ] هل تحتوي مسارات القوائم على ترقيم مقيد مع حد أقصى صريح (مثل 100 كحد أقصى)؟
- [ ] هل تم حماية حقول الفرز (`ORDER BY`) بواسطة قائمة بيضاء معتمدة (Whitelist)؟
- [ ] هل تفرض العمليات المالية أو عمليات التعديل الحساسة ترويسة `Idempotency-Key`؟
- [ ] هل تم تنسيق التواريخ دائماً بصيغة UTC ISO 8601 (`2026-09-14T05:30:00Z`)؟
- [ ] هل تخلو متحكمات الـ HTTP من أي منطق أعمال أو استعلامات SQL مباشرة؟
