# معايير طبقة المنصة وجذر التكوين في Go (Go Platform Primitives & Composition Root)

تحدد هذه المهارة المعايير الإنتاجية الصارمة لتصميم وإدارة **طبقة المنصة (`internal/platform`)** وجذر التكوين والتجميع (`Composition Root`) وفق المعايير الرسمية للغة Go (`go.dev`). تمثل هذه الطبقة الأساس التقني الداخلي المشترك لكافة وحدات النطاق والتطبيقات، وتتميز بحتمية منطقها، وتنفيذها داخل الذاكرة (In-Process)، وخلوها التام من أي ارتباط بحزم أو خدمات المزودين الخارجيين (Zero External Vendor Coupling).

---

## المبادئ الأساسية لطبقة المنصة (Core Principles)

1. **الاستقلالية التامة عن حزم المزودين الخارجيين (Zero External Vendor Coupling)**:
   لا يُسمح لحزم طبقة المنصة باستيراد حزم تطوير برمجية خارجية لمزودي الخدمات أو المنصات السحابية. المنصة تحتوي فقط على حزم Go القياسية وأدوات تقنية داخلية حتمية ومحايدة.
2. **تجريد الوقت للاختبارات الحتمية (Deterministic Clock Abstraction)**:
   تجريد استدعاءات الزمن عبر واجهة `Clock` لتوفير `RealClock` في الإنتاج و `MockClock` في الاختبارات، مما يلغي تماماً بطء اختبارات الوحدة أو عدم استقرارها (Flaky Tests).
3. **المعرفات الموزعة القابلة للفرز زمنيًا (K-Sortable Time-Ordered IDs)**:
   اعتماد معيار UUIDv7 أو ULID في توليد المعرفات الفريدة لحماية فهارس B-Tree في قواعد البيانات من التفتت وتحقيق أعلى أداء إدراج.
4. **ناقل أحداث داخلي غير معرقل (Non-Blocking In-Process Event Bus)**:
   فصل ناشري الأحداث عن المشتركين بالذاكرة عبر قنوات مؤقتة (Buffered Channels) وإسقاط غير حاجب (`select` مع `default`) لمنع بطء أي مشترك من تعطيل مسار الطلب.
5. **سياق تتبع وتدقيق محمي وآمن (Type-Safe Context Propagation)**:
   استخدام مفاتيح سياق غير مصدرة (`type contextKey struct{}`) ودوال وصول ذات نوع آمن لاستخراج معرّفات الطلب والتتبع والمستخدمين بأمان تام ودون ذعر (Zero Panic).
6. **جذر التكوين الصريح والتفكيك المعكوس (Explicit Composition Root & Reverse Teardown)**:
   تجميع وبناء شجرة التبعيات يدوياً وبترتيب طوبولوجي صارم داخل `internal/platform/app` تطبيقاً لقاعدة Go الرسمية **"Accept interfaces, return structs"**، مع إدارة الإغلاق المتدرج المعكوس عبر `signal.NotifyContext`.

```text
└─────────────────────────────────────────────────────────────────────────┘
```

## مقارنة معمارية: المنصة (Platform) مقابل البنية التحتية (Infrastructure)

| وجه المقارنة | طبقة المنصة (`internal/platform`) | طبقة البنية التحتية (`internal/infrastructure`) |
| :--- | :--- | :--- |
| **النطاق والوظيفة** | قدرات تقنية مشتركة، أدوات حتمية، وجذر التكوين | محولات شبكية، اتصالات قواعد بيانات، كاش، ومزودين |
| **اتجاه الاعتمادية** | أدوات تقنية داخلية، خالية تماماً من SDKs الخارجية | محولات صادر تنفذ واجهات منافذ النطاق (Ports) |
| **أمثلة الحزم** | `clock`, `id`, `eventbus`, `concurrency`, `context`, `app` | `database`, `cache`, `broker`, `storage`, `external` |
| **طبيعة الأعطال** | أعطال منطقية داخلية، تزامن خيوط بالذاكرة | بطء الشبكة، انقطاع الخوادم البعيدة، نفاد المجمعات |
| **آلية الصمود** | تزامن آمن (Mutexes)، قنوات مؤقتة، مجمعات عمال | مهل زمنية (Timeouts)، قواطع دوائر، إعادة المحاولة مع التشتت |

## الممارسات المحظورة (Anti-Patterns)

| الممارسة المحظورة | سبب الفشل في بيئات الإنتاج | البديل المعماري الصحيح |
| :--- | :--- | :--- |
| استيراد حزم تطوير لمزودي SaaS في المنصة | كسر مبدأ العزل وتلويث المنصة باعتماديات خارجية | حصر مكتبات المزودين بالكامل في `internal/infrastructure` |
| الاعتماد المباشر على `time.Now()` في العمليات الحساسة | استحالة كتابة اختبارات وحدة سريعة وموثوقة | حقن واجهة `Clock` واستخدام `MockClock` في الاختبارات |
| حجب ناشري الأحداث في ناقل الأحداث الداخلي | مشترك بطيء يتسبب في تجميد مسار طلبات الـ HTTP | استخدام قنوات مؤقتة وإسقاط غير حاجب عبر `select/default` |
| استخدام مفاتيح نصية خام في `context.WithValue` | حدوث تصادم وتداخل في قيم السياق بين الحزم | استخدام أنواع غير مصدرة (`type contextKey struct{}`) |
| إغلاق الموارد بشكل عشوائي أو متوازٍ أثناء الإيقاف | انهيار الاستعلامات الجارية عند إغلاق قاعدة البيانات مبكراً | تفكيك الموارد بترتيب عكسي صارم (الخادم ──> العمال ──> قاعدة البيانات) |

## قائمة مراجعة الجودة لطبقة المنصة (Platform Checklist)

```text
[ ] تخلو حزم platform بالكامل من أي استيراد لمكتبات SaaS أو مزودين خارجيين
[ ] واجهة Clock مجردة وتوفر بديلاً وهمياً MockClock للاختبارات الحتمية
[ ] توليد المعرفات يعتمد نسقاً مرتباً زمنياً (UUIDv7 أو ULID) لحماية فهارس B-Tree
[ ] ناقل الأحداث (eventbus) محمي بـ sync.RWMutex ولا يحجب الناشرين أبداً
[ ] سياق التتبع يستخدم مفاتيح غير مصدرة ودوال استخراج آمنة دون ذعر
[ ] مجمعات العمال تحدد سعة طابور المهام وتطبق ضغطاً خلفياً عند الامتلاء
[ ] التبعيات تُبنى وتُربط يدوياً في جذر التكوين (internal/platform/app) بترتيب طوبولوجي
[ ] دورة إنهاء التشغيل تغلق الموارد بترتيب عكسي صارم لتاريخ إنشائها
```
