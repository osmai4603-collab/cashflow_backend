# أدوات المنصة العابرة للمجالات (Cross-Cutting Platform Primitives)

توفر أدوات المنصة حلولاً موحدة وعالية الاعتمادية للتحديات التقنية المتكررة في أنظمة المؤسسات المبنية بلغة Go: تجريد الوقت للاختبارات الحتمية، توليد المعرفات الموزعة، ناقل الأحداث الداخلي، إدارة التزامن والمجمعات، وسياق التتبع والتدقيق.

---

## 1. تجريد الوقت والاختبارات الحتمية (`platform/clock`)

تعتمد الأنظمة المؤسسية على الوقت في عمليات انتهاء الصلاحيات، الفترات الزمنية، وجدولة المهام. الاعتماد المباشر على `time.Now()` و `time.Sleep()` يجعل اختبارات الوحدة بطيئة وغير مستقرة (Flaky Tests).

### معيار التجريد

```go
type Clock interface {
    Now() time.Time
    Sleep(d time.Duration)
    Since(t time.Time) time.Duration
}
```

* في بيئة الإنتاج: يُحقن `RealClock` المستند لمكتبة `time` القياسية مع حفظ التوقيت بنظام **UTC** دائماً.
* في بيئات الاختبار: يُحقن `MockClock` يسمح بتقديم الوقت برمجياً عبر `Advance(duration)` أو ضبطه لحظياً دون أي انتظار فعلي للمؤقتات.

## 2. توليد المعرفات الموزعة والمرتبة زمنياً (`platform/id`)

تتطلب قواعد البيانات الحديثة مفاتيح أساسية فريدة عالمياً (Universally Unique) مع الحفاظ على الترتيب الزمني التصاعدي (K-Sortable):

### معيار UUIDv7 / ULID

* **مشكلة UUIDv4 التقليدي**: توليد عشوائي كامل يتسبب في تفتيت فهارس B-Tree (Index Fragmentation) وانخفاض أداء الإدراج في قواعد البيانات.
* **الحل عبر UUIDv7**:
  * تضمين طابع زمني بالمللي ثانية (48 بت) في البداية لضمان التسلسل والترتيب التلقائي.
  * ملء البتات المتبقية (80 بت) بعشوائية تشفيرية آمنة لمنع التصادم عبر الخوادم الموزعة.

## 3. ناقل الأحداث الداخلي غير المعرقل (`platform/eventbus`)

يسمح ناقل الأحداث في الذاكرة بفصل ناشري الأحداث عن المشتركين دون الحاجة لوسيط رسائل خارجي للعمليات الداخلية السريعة (مثل تحديث واجهات WebSocket أو إطلاق مهام تدقيق جانبية).

### مبدأ التوزيع غير المعرقل (Non-Blocking Backpressure)

يجب ألا يؤدي بطء مشترك واحد إلى تعطيل عملية النشر أو تجميد مسار الـ HTTP:

```go
func (b *EventBus) Publish(ctx context.Context, topic string, payload any) error {
    event := Event{Topic: topic, Payload: payload, Timestamp: time.Now().UTC()}
    b.mu.RLock()
    defer b.mu.RUnlock()

    for ch := range b.subscribers[topic] {
        select {
        case ch <- event:
            // تم التسليم بنجاح للقناة المؤقتة
        case <-ctx.Done():
            return ctx.Err()
        default:
            // القناة ممتلئة! يتم إسقاط الرسالة أو تسجيلها بدلاً من حجب الخيط
        }
    }
    return nil
}
```

## 4. مجمعات المعالجة ومحددات التزامن (`platform/concurrency`)

إطلاق Goroutines بلا حساب (`go doWork()`) يؤدي إلى استنزاف الذاكرة وموت العملية تحت الضغط العالي.

### القواعد الصارمة

1. استخدام مجمعات مهام ذات سعة محددة (`WorkerPool`) مع قنوات استقبال ذات سعة قصوى (Bounded Queue).
2. تطبيق ضغط خلفي (Backpressure) برفض المهام الجديدة أو إرجاع خطأ إشغال عند امتلاء الطابور.
3. التفكيك المنظم والانتظار عبر `sync.WaitGroup` عند إيقاف الخادم.

---

## 5. سياق التتبع والتدقيق الآمن (`platform/context`)

وفق توجيهات Go الرسمية (`go.dev/blog/context`)، يجب حماية سياق الطلب من تداخل الحزم:

1. **مفاتيح سياق غير مصدرة (Unexported Keys)**:

   ```go
   type contextKey struct{ name string }
   var traceContextKey = contextKey{name: "trace_id"}
   ```

2. **دوال وصول ذات نوع آمن (Type-Safe Accessors)**:
   توفير دوال مثل `WithTraceID(ctx, id)` و `TraceIDFromContext(ctx)` دون كشف مفتاح السياق أو إجراء تحويلات أنواع خطرة (Unsafe Type Assertions).
3. **التوقيت الموحد**: حفظ كافة أوقات التدقيق بتوقيت **UTC** حصراً.
