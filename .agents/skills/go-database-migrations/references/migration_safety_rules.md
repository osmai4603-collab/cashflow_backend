# قواعد أمان الترحيل أثناء تشغيل الخدمة (Migration Safety Rules)

تحدد هذه الصفحة الأوامر المحظورة والآمنة عند تطبيق ترحيلات PostgreSQL على قواعد بيانات حية تخدم طلبات فعلية.

---

## مصفوفة الأوامر المحظورة والبدائل الآمنة

| العملية | الأمر الخطير (ممنوع في الإنتاج) | العواقب | البديل الآمن المعتمد |
| :--- | :--- | :--- | :--- |
| **إنشاء فهرس** | `CREATE INDEX idx_name ON table (col);` | يقفل الجدول بالكامل ضد الكتابة حتى اكتمال الفهرسة | `CREATE INDEX CONCURRENTLY idx_name ON table (col);` |
| **إضافة عمود إلزامية** | `ALTER TABLE t ADD COLUMN c INT NOT NULL;` | يفشل فوراً إذا كان الجدول يحتوي على بيانات | أضف العمود كـ Nullable أولاً، املأ البيانات، ثم أضف قيد `NOT NULL`. |
| **تغيير اسم عمود** | `ALTER TABLE t RENAME COLUMN c TO c_new;` | يكسر جميع نسخ التطبيق القديمة فوراً | نمط Expand and Contract: أضف عموداً جديداً، زامن البيانات، ثم احذف القديم لاحقاً. |
| **حذف جدول أو عمود** | `DROP TABLE t;` أو `DROP COLUMN c;` | فقدان فوري للبيانات وانهيار الاستعلامات القديمة | التأكد من إزالة كافة مراجع الكود أولاً، والانتظار دورة نشر كاملة قبل الحذف. |
| **إضافة مفتاح أجنبي** | `ALTER TABLE t ADD CONSTRAINT fk ...;` | يفحص كافة الصفوف مع قفل الجدول بالكامل | استخدام `NOT VALID` أولاً، ثم `VALIDATE CONSTRAINT` بشكل منفصل. |
