   - تم التحقق من تفعيل ظهور لوحة `[ REAL USER MONITORING (RUM) ]` تلقائياً بمجرد تجاوز عدد العينات للصفر (`samples_count > 0`) وعرض قيم LCP و INP و CLS و TTFB المحسوبة ديناميكياً.
5. **استهلاك الموارد وخفة السكريبت:**
   - يستهلك سكريبت `tool/monitor.sh` أثناء التحديث المستمر كل 0.5s:
     - المعالج (CPU): **1.9%** فقط.
     - الذاكرة (RAM): **~4 MB RSS** فقط.
   - مما يثبت عدم تأثيره إطلاقاً على أداء السيرفر أو النظام.

## 5. الأخطاء البرمجية التي تم اكتشافها وتصحيحها

خلال الاستكشاف الأولي لمسارات الـ API بالكامل، تم رصد أخطاء مسح (Row Scanning) وتصحيحها فوراً:

1. **مستودع المستخدمين ([internal/adapters/storage/user/postgres_repo.go](file:///home/osm/StudioProjects/cashflow/cashflow_backend/internal/adapters/storage/user/postgres_repo.go)):**
   - *المشكلة:* كان حقل `email_notifications_enabled` مفقوداً في دالة `rows.Scan` عند سرد المستخدمين (`List`)، مما كان يسبب فشل الاسترجاع بخطأ 500 (`failed to scan user row`).
   - *الإصلاح:* إضافة الحقل بالترتيب المتطابق مع استعلام `selectUserFields`.
2. **مستودع الشركات ([internal/adapters/storage/company/postgres_repo.go](file:///home/osm/StudioProjects/cashflow/cashflow_backend/internal/adapters/storage/company/postgres_repo.go)):**
   - *المشكلة:* غياب 5 أعمدة جديدة في `rows.Scan` لـ `List` (`attendance_kiosk_mode`, `attendance_kiosk_delay`, `overtime_company_threshold`, `auto_check_out_tolerance`, `lc_journal_id`).
   - *الإصلاح:* إدراج المتغيرات المطابقة في دالة المسح.
3. **مستودع المصروفات ([internal/adapters/storage/expense/postgres_repo.go](file:///home/osm/StudioProjects/cashflow/cashflow_backend/internal/adapters/storage/expense/postgres_repo.go)):**
   - *المشكلة:* حقلا `description` و `refuse_reason` يقبلان قيمة فارغة `NULL` في قاعدة البيانات، بينما الكود يقابلها بنوع `string` بسيط دون معالجة القيمة الفارغة مما أدى لخطأ `can't scan NULL into *string`.
   - *الإصلاح:* استخدام دالة `COALESCE(e.description, '')` و `COALESCE(e.refuse_reason, '')` داخل الاستعلام.
